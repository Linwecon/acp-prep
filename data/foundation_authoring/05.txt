5.1|微调定义|微调与仅修改提示词的本质区别是什么？|微调通过训练更新参数，提示词只改变输入。|微调是在已有模型基础上适配任务，不等于从零预训练。
5.1|适用目标|统一客服措辞与查询当天库存，哪个更接近微调常见目标？|统一任务行为和措辞更接近微调目标；库存应查询实时系统。|微调也能学到知识，但不保证及时更新和可靠追溯。
5.2|先建基线|为什么决定微调前要评估现有模型和提示词方案？|确认真实缺口，并建立可以比较的基线。|否则无法区分训练收益与提示词、数据或评测条件变化。
5.3|SFT|监督微调 SFT 使用哪一类训练信号？|使用任务输入与期望输出等有监督样本。|SFT 描述监督训练方式，是否全参更新是另一维度。
5.3|全参微调|全参微调与 LoRA 在可训练参数范围上有什么区别？|全参通常更新全部模型权重；LoRA 通常冻结基座并训练低秩增量。|范围不同会影响梯度、优化器状态和训练资源开销。
5.3|PEFT|PEFT 与 LoRA 是什么关系？|PEFT 是参数高效微调方法类别，LoRA 是其中一种。|不能把所有参数高效方法都当成同一个算法。
5.6|低秩直觉|LoRA 为什么用两个较小矩阵表示权重变化？|用低秩结构近似任务需要的更新，以减少可训练参数。|这是对更新的结构约束，不代表原模型被删除或没有训练。
5.3|QLoRA|QLoRA 在 LoRA 基础上主要增加了什么资源节省思路？|把冻结基座以低比特形式存储，训练适配参数。|基座量化与适配器训练是两个步骤，效果仍需要评测。
5.4|蒸馏|知识蒸馏中的教师和学生各自扮演什么角色？|教师提供监督信号，学生通过训练学习相应行为。|监督可以是生成答案或其他信号；不是直接把教师文件缩小。
5.5|数据质量|一万条互相矛盾的标注与较少但一致的高质量标注，为什么不能只比较数量？|错误和矛盾会向训练传播不稳定模式。|样本数量、覆盖和质量共同影响结果，扩大坏数据可能更糟。
5.5|训练格式|JSONL 数据文件通常如何组织多条训练样本？|每行一个独立 JSON 对象，字段遵循训练接口要求。|语法合法只是第一步，还要检查角色、标签和内容质量。
5.5|数据拆分|训练集、验证集、测试集分别用来做什么？|训练参数、选择超参数或检查训练过程、最终独立评估。|测试集不应参与反复调参，否则评估会偏乐观。
5.5|数据泄漏|同一段制度的近重复问答同时出现在训练集和测试集，会造成什么？|测试结果可能因记忆或高度相似而虚高。|应按来源或实体分组拆分，并检查跨集合的近重复。
5.7|Loss|训练 loss 持续下降，是否等于业务能力持续提高？|不是，可能只对训练样本拟合得更好。|需要同时看验证表现和实际业务指标，防止把优化目标当最终效果。
5.7|Epoch|训练数据完整经过模型一次，通常称为什么？|一个 epoch。|增加轮次会增加学习机会，也可能加重过拟合，并非越多越好。
5.7|学习率|学习率过大和过小，各可能出现什么表现？|过大可能震荡或发散；过小可能学习缓慢或进展不足。|合适范围与模型、数据、优化器和训练设置有关。
5.7|批量大小|批量大小增加时，为什么要同时关注显存和优化行为？|每步处理更多样本会改变资源需求和梯度估计特征。|不能只按“越大越快”判断，还要结合有效批量和学习率。
5.6|Rank|LoRA 的 rank 提高通常意味着什么取舍？|适配容量增大，也会增加参数和资源开销。|更高 rank 不保证更好，需要验证任务收益和过拟合风险。
5.8|检查点|为什么要保存中间 checkpoint，而不只留最后一步？|验证集上的最佳模型可能早于最后一步，也便于恢复训练。|选择模型应依据预定评价规则，而不是单看训练结束时间。
5.9|双层评估|分类模型输出 JSON 很规范，但标签经常错，应分别评估什么？|分别评估格式合规率和分类正确性。|格式正确不代表业务判断正确，两类失败需要不同改进。
5.2|方案判断|机器人知识答对但语气不统一，第一步一定要微调吗？|不一定，先尝试清晰规则、示例和评测，再决定是否训练。|微调有数据、训练和维护成本，应该解决可证明的剩余缺口。
5.4|教师数据审查|教师模型生成了一批训练答案，能不检查直接训练吗？|不能，应抽检、过滤事实错误和不符合格式的样本。|学生可能复制教师错误，教师规模更大不等于样本绝对可靠。
5.5|类别不平衡|训练样本中 95% 都是普通咨询，紧急工单识别差该先查什么？|检查类别覆盖、标注标准和采样策略。|总体准确率可能掩盖稀少但重要类别的失败。
5.7|过拟合判断|训练 loss 下降而验证 loss 持续上升，优先怀疑什么？|过拟合，也要检查数据分布与验证流程。|可以考虑早停、改善数据或调整容量，但应先确认测量可靠。
5.7|有效批量计算|单卡微批量为 2、梯度累积 8 步，忽略多卡时有效批量是多少？|16 个样本。|2×8=16；梯度累积减少单步显存需求，但不完全等同于所有计算特性都一样。
5.6|适配器部署|训练好的 LoRA 适配器能任意挂到另一版本基座吗？|不能随意替换，需核对基座版本、结构和目标层兼容性。|适配器表示针对特定基座的增量，版本变化可能破坏效果。
5.9|回归测试|专业任务提升后，为什么还要检查原有通用能力和安全表现？|训练可能导致能力退化或新的不当行为。|局部提升不代表整体可上线，应保留通用与风险回归集。
5.10|知识更新|制度每天变化，靠每天微调来更新知识有什么代价？|训练和验证周期长，版本维护复杂，知识溯源不便。|优先评估实时检索或工具；行为适配与知识更新可分开解决。
5.10|上线验证|新模型离线测试提升，应立即替换全部流量吗？|应先做受控验证或灰度，监控关键指标并保留回滚方案。|真实请求分布可能不同，部署流程也是质量保障的一部分。
5.8|全流程|排出一次可复现微调的主要步骤。|定义目标与基线 → 准备并拆分数据 → 训练 → 验证选点 → 独立测试 → 灰度部署。|同时记录数据、模型、代码和超参数版本，才能解释结果并重现。
