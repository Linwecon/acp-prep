9.1|API 作用|模型 API 与在网页聊天的主要区别是什么？|API 让应用程序按接口协议发送输入并处理响应。|业务集成需要代码处理鉴权、参数、错误和输出，而不只是手工对话。
9.2|调用要素|一次模型请求通常需要明确哪些基本信息？|服务地址、认证凭据、模型标识和请求内容。|地址与模型必须匹配所选服务，不能只换一个密钥就假定完全兼容。
9.2|兼容含义|“OpenAI 兼容接口”是否表示所有参数和功能完全相同？|不是，兼容范围和扩展能力需查目标服务文档。|通用客户端可能可用，但模型名、错误、参数支持和返回字段仍有差异。
9.3|密钥职责|API Key 的主要作用是什么？|作为服务认证或授权凭据识别调用方。|它是秘密，不应出现在公开仓库、前端代码或无保护日志中。
9.3|环境配置|把密钥从代码改到环境变量中，是否就能保证永不泄露？|不能，还要保护部署环境、日志、权限和配置文件。|环境变量减少硬编码风险，但不是完整的秘密管理方案。
9.4|模型参数|请求中的 model 字段通常用来指定什么？|要调用的模型或服务标识。|应使用当前账号和地域可访问的有效标识，不能把展示名称任意代入。
9.4|输出上限|设置输出 Token 上限的主要目的是什么？|控制生成长度与相关资源消耗。|它不保证答案完整；上限太小可能导致截断或结构不完整。
9.4|采样参数|API 中 temperature 与输出长度上限分别控制什么？|前者影响采样分布，后者限制输出规模。|不要把降低随机性和缩短回答混为同一操作。
9.5|消息列表|messages 中为什么既可以有 user，也可以有 assistant 历史？|共同描述当前任务的对话上下文。|历史应来自可信会话记录，并注意容量、隐私和有效性。
9.5|多轮传递|第三轮请求只发新问题，与传入必要历史相比会损失什么？|可能损失被指代对象、既定约束和先前结论。|应用管理上下文，不能假设所有模型接口天然记住前两次调用。
9.6|SSE|流式 API 中 SSE 的主要用途是什么？|通过持续连接向客户端逐步发送事件或内容片段。|它是传输方式，不代表每个事件都恰好对应一个完整词或句子。
9.6|增量拼接|收到多个流式增量片段后，客户端通常需要做什么？|按顺序累积、展示，并处理结束和错误状态。|不能把每个增量误当成完整回答覆盖掉此前文本。
9.6|空片段|流式事件没有正文内容时，程序一定应该报错吗？|不一定，可能是角色、工具信息或结束状态等事件。|应按接口协议区分事件类型，而不是假定每段都有文本。
9.7|工具定义|从 API 角度看，工具的 JSON Schema 有什么价值？|表达名称、用途和参数结构，帮助生成与验证调用参数。|Schema 只规定格式，业务权限和参数语义仍由执行端检查。
9.7|工具结果|工具执行完成后，为什么要回传调用标识和对应结果？|让模型或应用把结果关联到正确的工具调用。|多个并行调用时尤其需要关联关系，不能把结果顺序随意混用。
9.8|错误分类|认证失败和临时限流应采用完全相同的处理方式吗？|不应，认证失败应修复凭据或权限，临时限流才可能适合退避重试。|先分类错误，避免无意义重试加重负载。
9.8|退避|指数退避加随机抖动主要缓解什么？|减少大量客户端同步重试造成的集中请求峰值。|还要限制最大重试次数和总时长，不能无限等待。
9.9|Token 费用|为什么输入与输出费用应分别估算？|服务可能对两类 Token 采用不同计价规则。|还要考虑缓存、模型和套餐等条件，不能用一个通用价格套所有请求。
9.10|Batch|什么任务通常适合异步批量调用，而非等待实时回答？|大量可延后完成的分类、抽取或离线生成任务。|批量模式的时效、额度和费用取决于服务，实时交互未必适合。
9.11|请求追踪|保存 request ID 或业务请求标识有什么帮助？|关联调用、错误和业务结果，便于排查问题。|追踪标识通常比记录完整敏感请求更安全，也更利于跨系统定位。
9.2|字段校验|HTTP 请求成功，但返回 JSON 缺少业务必填字段，应用应怎么做？|按业务契约判为不合格，执行有限纠错、重试或降级。|传输成功、JSON 合法与业务成功是三种不同状态。
9.3|公开前端|为什么不应把长期有效模型密钥写进公开网页 JavaScript？|用户可以读取前端资源并复制密钥使用。|应通过受控后端或合适的短期授权方案管理访问。
9.4|窗口超限|输入已经超过模型窗口，只降低输出上限一定能成功吗？|不一定，输入本身可能已超限，需要缩减或拆分内容。|先区分输入限制、总窗口和输出限制，再采取对应措施。
9.6|流中断|回答已显示一半时连接断开，为什么不能把它当作完整成功？|内容可能截断，甚至缺少关键条件或 JSON 结尾。|应标记未完成并提供重试或恢复路径，避免静默使用半成品。
9.7|工具安全|模型返回查询参数中的非法员工编号，应该在哪一步拦截？|在工具真正执行之前进行格式、范围和授权检查。|不能把验证责任全部交给模型或事后解析。
9.8|超时与副作用|创建工单接口超时后，直接重发相同请求可能造成什么？|第一次可能已成功，导致重复工单。|使用幂等键或查询执行状态，区分响应丢失与执行失败。
9.9|费用计算|假设输入每千 Token 0.002 元、输出每千 0.006 元；输入 2000、输出 500，本次费用多少？|0.007 元。|2×0.002+0.5×0.006=0.007；这里是题设价格，不是任何服务的实时报价。
9.10|批量对账|批量任务返回结果顺序与提交顺序不同，怎样正确匹配？|为每条请求设置唯一标识，按标识关联结果。|不能只按数组位置匹配，应同时处理失败、重复和缺失记录。
9.8|配额区别|RPM 未超限但 TPM 超限，说明哪类限制被触发？|每分钟 Token 量限制，而非请求次数限制。|长输入或长输出可能让少量请求也消耗大量 Token。
9.11|完整调用|列出一个可靠模型调用函数至少应处理的五件事。|凭据管理、参数校验、超时、错误分类与有限重试、结果校验和追踪。|可列更多；重点是把不成功和不完整的路径也设计进去。
