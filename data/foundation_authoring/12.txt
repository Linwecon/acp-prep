12.1|框架价值|大模型应用框架主要帮助解决什么问题？|组织模型、提示词、检索、工具和状态等组件，减少重复工程。|框架不自动增加模型知识或保证输出正确。
12.1|是否必需|只有一次简单模型调用的脚本，一定需要引入大型框架吗？|不一定，直接使用适当 SDK 可能更清楚。|框架收益应大于学习、依赖和调试成本。
12.2|组件组合|把提示模板、模型调用、输出解析分成组件有什么价值？|便于单独测试、替换和复用。|组件化让故障位置更清楚，但仍需维护输入输出契约。
12.2|提示模板|框架中的提示模板与普通字符串相比，重点增加什么管理能力？|变量化与复用，帮助稳定组织任务输入。|模板仍需验证变量和安全边界，不是写好一次就永远可靠。
12.2|输出解析器|输出解析器负责什么，不能代替什么？|把输出转换为预期结构，不能代替事实和业务正确性验证。|解析成功只说明满足相应结构规则。
12.2|状态管理|应用框架保存对话状态时，为什么需要会话标识？|把不同用户或任务的历史分隔开。|缺少隔离可能串话或泄露数据，不能用一个全局列表保存所有历史。
12.3|LlamaIndex 定位|LlamaIndex 的核心关注点可以怎样概括？|围绕数据接入、索引、检索及与模型结合的应用流程。|它适合数据密集型应用，但实际效果仍依赖数据和配置。
12.3|索引|构建索引与真正生成回答分别发生在什么阶段？|索引组织可检索数据，回答阶段检索并调用生成模型。|两者相关但不同，索引建好不代表每次回答都会正确。
12.4|框架比较|比较应用编排框架与数据索引框架时，应先问什么？|当前主要难点是流程组织，还是数据接入与检索。|功能可以重叠，不应仅凭名称断言某框架绝对不能做某任务。
12.5|解析工具|为什么文档解析工具与向量数据库不能互相替代？|前者提取并整理内容，后者组织向量存储与检索。|数据库无法补回解析阶段遗漏的表头或文字。
12.5|格式选择|读取普通文本 PDF 和扫描 PDF，工具链可以完全一样吗？|不一定，扫描件通常需要 OCR 或视觉解析。|先判断文件实际内容形式，扩展名相同不代表解析需求相同。
12.5|表格处理|表格解析结果若只剩一串文字，对 RAG 有什么影响？|行列对应和条件可能丢失，导致检索或回答错误。|应保留标题、表头及单元格关系，必要时补充结构化表示。
12.6|AgentScope|AgentScope 更接近哪类工具定位？|用于构建 Agent 应用及协作流程的框架。|具体接口随版本变化，理解职责比背某个旧函数名更重要。
12.6|Dify|Dify 的低代码能力主要减少哪类工作？|减少应用编排和界面配置中部分手工开发工作。|模型、知识库、权限和部署仍需要正确配置与验证。
12.7|RAGAS|把 RAGAS 接入应用链路主要是为了什么？|对检索生成等环节进行结构化评估。|评测工具不直接替你修复知识库，也不替代人工标准制定。
12.7|Gradio|快速演示一个模型交互界面时，Gradio 可以承担什么？|快速构建输入输出交互 Demo。|演示界面便利，不等于已经具备完整生产授权和运维机制。
12.7|FastAPI|FastAPI 在模型应用里通常承担哪类职责？|把应用逻辑封装为 HTTP 接口并处理请求响应。|它不是模型，也不是向量检索算法，服务可靠性仍需配套设计。
12.2|版本边界|教程中的旧 Memory 或 Chain 示例无法导入时，首先应该核对什么？|安装版本、教程版本及官方迁移说明。|不同版本可能调整抽象和包位置，不宜随机混装直到碰巧能运行。
12.8|依赖管理|为什么应保存依赖版本或锁文件？|使开发、测试和部署环境更容易复现。|只记录顶层框架名称，不能保证间接依赖和运行行为一致。
12.8|观测能力|框架调用失败时，为什么需要查看实际请求和组件轨迹？|封装可能隐藏参数、重复调用或错误传播位置。|记录必要且脱敏的追踪信息，才能区分框架问题和服务问题。
12.3|索引持久化|每次用户提问都重新解析全部文档并生成向量，通常有什么问题？|增加延迟和费用，也容易造成版本不一致。|适合复用已建立索引，并在数据变化时执行受控更新。
12.4|组合应用|能否用一种框架管理工作流，再接入另一种的数据检索组件？|可以，但应明确接口、状态归属和依赖边界。|组合有收益也有复杂度，避免两套组件重复管理同一状态。
12.5|工具选择|文档以复杂表格为主，选解析工具时应怎样验证？|用真实样本检查表头、行列和合并单元格是否保留。|不能仅凭支持 PDF 的说明判断是否适合具体材料。
12.6|协作设计|用多 Agent 框架后，是否自动拥有可靠的任务分工？|不是，仍需定义角色、消息协议和结束条件。|框架提供机制，任务设计决定协作是否有效。
12.6|工作流排错|低代码工作流最终答错，应只更换大模型节点吗？|不应先盲换，应逐节点检查输入、检索结果、映射和输出。|可视化流程仍会有数据连接错误，定位比试错更有效。

12.8|迁移验证|升级框架后代码能启动，是否说明升级成功？|还需要验证核心任务、状态、工具调用和性能的回归表现。|语法兼容不代表语义和默认行为完全一致。
